#+title: Конфігурація

Компонент проєкту називається ~bwm-mcp~ (код проєкту ~bwm~ і назва компонента ~mcp~), а крейт —
~bwm-mcp~. Сервер не використовує жодного стороннього крейта для самого протоколу =mcp=: =json-rpc=
реалізовано напряму, як у ~am-mcp~ / ~fm-mcp~, див. [[file:main.org][~main.org~]]. Шифрування й робота з сейфом — через
офіційні (хоч і позначені "internal, do not use") =Rust= підкрейти ~sdk-internal~. Готовий фасад
~bitwarden-pm~ (усе одним крейтом) свідомо не використано: він безумовно тягне ~bitwarden-importers~ /
~bitwarden-exporters~ / ~bitwarden-send~ тощо, непотрібні нам, а ~bitwarden-importers~ додатково тягне
~keepass~, чия конкретна дозволена версія (~<0.14~ за вимогою самого ~sdk-internal~) конфліктує версіями
~aes~ / ~cipher~ з рештою графу. Замість фасаду — прямі підкрейти: ~bitwarden-core~ (з фічею ~internal~),
~bitwarden-vault~, ~bitwarden-auth~, ~bitwarden-sync~, ~bitwarden-generators~ — жоден із них ~keepass~ не
чіпає.

* =tokio=

Можливості: асинхронне читання й запис стандартного вводу-виводу (~io-std~, ~io-util~) — так сервер
спілкується з клієнтом =mcp=; ~rt-multi-thread~ — те саме середовище виконання, що використовує сам
~bw~ (=cli= із ~sdk-internal~ бере ~current-thread~, але наш сервер обробляє запити паралельно, тож
потрібен багатопотоковий рантайм).

#+begin_src toml :noweb-ref Залежності
  tokio = { version = "*", features = ["macros", "rt-multi-thread", "io-std", "io-util"] }
#+end_src

* ~sdk-internal~

Не публікується на =crates.io=, тож залежність — через ~git~ на конкретний ~rev~ (не ~"*"~ — для
~git~-залежності це єдиний спосіб відтворюваності, бо семантичного версіювання на =crates.io= тут
немає; звичайне правило проєкту про ~"*"~ для =crates.io=-залежностей тут не застосовне саме через
це). Фіча ~internal~ на ~bitwarden-core~ потрібна для доступу до персонального сейфа (без неї крейт
обмежений =Secrets Manager=, як публічний фасад ~bitwarden~).

Тег ~rust-v3.0.0~ (єдиний випущений) виявився непридатним: ~bitwarden-crypto~ на ньому прямо обмежує
~typenum <1.20.0~, а транзитивна ~rsa~ (без верхньої межі, ~^0.7~) з часу випуску тега лишилась лише з
~crypto-bigint 0.7.5~ на =crates.io= — усі версії ~0.7.0~–~0.7.4~ відтоді відкликано (~yanked~), а
саме ~0.7.5~ підняла свою вимогу до ~hybrid-array ^0.4.12~, чий ~typenum ^1.20~ прямо конфліктує з
обмеженням ~bitwarden-crypto~ — незадовольнюваний конфлікт версій, не залежний від нашого
~Cargo.toml~. На гілці ~main~ це вже виправлено (~typenum <1.21.0~), просто новий тег ще не випущено.

Залежність — на власний форк ~EugineKosenko/sdk-internal~ (гілка ~bwm-mcp-item-support~), не на
апстрім: там додано три точкові виправлення, знайдені при написанні цього компонента.
1. ~CipherSyncHandler~ — апстрім не синхронізує ~ciphers~ в локальний репозиторій узагалі (жоден
   ~SyncHandler~ для них не існує, на відміну від ~folders~ / ~sends~).
2. Реекспорт ~CipherCreateRequest~ / ~CipherEditRequest~ / ~CipherPartialEditRequest~ — в апстрімі
   приватні, всупереч власному ~README.md~ крейта, що прямо називає їх "Public input DTOs".
3. ~login_password()~ ніколи не викликає ~init_user_id()~ — після успішного входу
   ~Client::internal::get_user_id()~ лишався ~None~, тож ~CiphersClient::create()~ (яка його читає)
   падала з ~NotAuthenticatedError~ навіть при робочому вході й сейфі (~list~ / ~get~ це не зачіпало —
   вони ~user_id~ не читають). Виводимо ~user_id~ із ~sub~-клейма самого access-токена
   (~JwtToken~, уже публічний із ~bitwarden_core::auth~).

Форк — точкові коміти поверх того самого ~rev~ апстріму, на якому вже стояли до цього. Усі підкрейти
нижче — той самий форк і той самий ~rev~, бо мають узгоджуватися між собою в межах одного знімка
~workspace~ (і, найважливіше, щоб тип ~bitwarden_core::Client~ був рівно один на весь граф
залежностей — точковий пін лише ~bitwarden-vault~ на форк дав би два різні несумісні типи ~Client~ з
різних джерел).

* Спільний диск для ~target/~

За `build-cache.md`: важкі build-артефакти — на окремому диску, не в робочому каталозі проєкту. Шлях —
рівно два рівні: назва проєкту (~bw-mcp~), тоді назва компонента (~bwm-mcp~). Сам файл —
машинно-специфічний абсолютний шлях, тож у ~.gitignore~ (див. [[file:gitignore.org][~gitignore.org~]]), не в git.

#+begin_src toml :mkdirp yes :tangle .cargo/config.toml
  [build]
  target-dir = "/var/ftp/cache/rust/target-sdd/bw-mcp/bwm-mcp"
#+end_src
